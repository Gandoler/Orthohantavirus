# i18n: Russian As Default With Language Switcher

Дата: 2026-05-13
Статус: draft

## Цель

Сделать русский язык интерфейса базовым (домен `ортхохантавирус.рф` — это
обещание перед пользователем), а английский — равноценным вторым, с
переключалкой языков, и SEO-чистыми URL для обеих локалей. Не "переведённый
интерфейс на коленке", а проектная инфраструктура локализации, в которую
позже легко добавить третий язык.

## Что Сейчас

- весь UI на английском, включая публичные страницы;
- в HTML head `<html lang="en">`;
- `index.html` рендерит SSR-fallback на английском (h1, ul);
- API ответы и значения news.language пока в `ru`, но интерфейс это не
  использует;
- даты форматируются через `Intl.DateTimeFormat("en", ...)` — захардкожено.

## Архитектурные Решения

### URL Стратегия

Выбран **path-prefix**:

- `https://ортхохантавирус.рф/` — русская версия (default);
- `https://ортхохантавирус.рф/en/` — английская версия;
- `https://ортхохантавирус.рф/methodology` — ru;
- `https://ортхохантавирус.рф/en/methodology` — en.

Почему path-prefix, а не поддомен:

- одно SSL, один Caddy блок, один origin на GA/Umami;
- hreflang дружит с обоими, но path проще выкатить инкрементально;
- для en можно позже легко переехать на поддомен без слома ссылок (308).

Detection-flow для нового пользователя:

1. URL содержит `/en/` → язык = en;
2. иначе — язык = ru;
3. явный выбор в переключалке кладётся в `localStorage` и в cookie
   `orthohantavirus-locale`;
4. при следующем входе на корень читаем cookie; если en — редиректим на
   `/en/` (308 на edge через Caddy `@en_lang` matcher или клиентский
   редирект в `main.tsx` до маунта).

Accept-Language **не** влияет на default. Сайт открыт по русскому домену —
русский же по умолчанию.

### Библиотека Перевода

Выбираем `react-i18next` + `i18next`:

- зрелая, плагины для language-detection и backend-loading;
- поддерживает интерполяцию, plurals, namespaces;
- лёгкий runtime (~15 КБ gzip);
- без vendor-lock — JSON-файлы;
- альтернатива `lingui` чуть приятнее API но даёт меньше плагинов.

Хранение строк: JSON-файлы по неймспейсам в `frontend/src/locales/`:

```
frontend/src/locales/
  ru/
    common.json     # shell, buttons, status labels
    map.json        # layer toggles, legend, region panel
    news.json       # news card, filters
    admin.json      # admin console
    seo.json        # title, description, og
  en/
    common.json
    map.json
    news.json
    admin.json
    seo.json
```

Базовый язык исходник = русский. Английский файл — перевод от русского,
а не наоборот. Это меняет ощущение продукта: писать строки сразу
по-русски с правильной интонацией, а не переводить с шероховатого
английского.

## Фазы

### Фаза 1: Каркас (P0, 2-3 дня)

1. установить `i18next`, `react-i18next`, `i18next-browser-languagedetector`;
2. создать `frontend/src/i18n.ts` с initReactI18next, ресурсами из JSON,
   fallback = `ru`, поддерживаемые = `["ru", "en"]`;
3. подключить в `main.tsx` до `ReactDOM.render`;
4. добавить `<html lang>` через `useEffect` в `App`, синхронно с i18next;
5. вытащить в `useTranslation()` и `t("key")` 10-15 первых строк
   (`Hide feed`, `Show feed`, `Cases`, `Outbreaks`, `Heatmap`, `News`,
   `Refresh`, `Light`, `Dark`, заголовок) — проверить, что переключение
   работает в dev;
6. написать smoke unit-test, который меняет locale и проверяет, что
   `t("layer.cases")` отдаёт `Случаи` для ru и `Cases` для en.

### Фаза 2: Извлечение Строк (P0, 4-5 дней)

1. пройти `App.tsx` сверху вниз, заменить все литералы UI на `t()` вызовы;
2. отдельно вытащить ARIA `aria-label` строки и placeholders;
3. отдельно вытащить SEO-meta в `seo.json` и поднять через
   `document.title` + meta description manager при смене маршрута/языка;
4. написать русские строки сначала, потом перевести английские;
5. ревью русских строк с фокусом на медтерминологию: "случаи",
   "подтверждённые", "очаги", "верифицированные обновления";
6. форматирование чисел и дат вынести в `frontend/src/format.ts` с
   параметром locale, а не захардкоженным "en";
7. удалить из `index.html` SSR-fallback на английском, заменить на
   двуязычный или подменять серверно по пути.

### Фаза 3: Switcher UI (P0, 1 день)

1. в floating topbar справа добавить компактный 2-state toggle "RU / EN"
   рядом с theme-кнопкой;
2. на mobile — внутри top action-меню;
3. клик: меняет `i18n.changeLanguage`, обновляет URL: ru ↔ en префикс,
   сохраняет cookie и localStorage;
4. визуально: подчёркнутая активная буква, без флагов (флаг ≠ язык, и
   тема медицинская — флаги тут лишние);
5. компонент `LanguageSwitcher` отдельным файлом, протестировать на смену
   языка с открытыми feed-sheet и region-panel — состояние не теряется.

### Фаза 4: Маршрутизация И SEO (P0, 2-3 дня)

1. ввести минимальный роутер: либо `react-router`, либо собственный
   `useLocale()` хук, читающий префикс из `window.location.pathname`;
2. при смене языка `history.replaceState` обновляет URL;
3. canonical и hreflang генерируются динамически в `<head>` через
   `useHead` или вручную через `document.querySelector`;
4. SSR-страницы (новости, страны, вспышки) на бэке: учитывать accept-path
   `/en/...`, отдавать локализованный HTML с `<html lang="en">` и
   правильным `og:locale`;
5. Caddy: обрабатывать `/en/*` и пробрасывать тот же `frontend:8080`,
   главное — без cache-инверсии (один и тот же index.html ОК, React
   разберётся);
6. sitemap: каждая страница перечислена в обеих локалях с `xhtml:link
   rel="alternate" hreflang=...`;
7. обновить `index.html`: убрать жёстко зашитый `lang="en"`, поставить
   `lang="ru"` как default; добавить альтернативные og:locale.

### Фаза 5: Бэкенд И Контент (P1, 4-5 дней)

1. в map-api и news-service принимать `?lang=ru|en` или `Accept-Language`;
2. отдавать локализованный `label`, `summary` если есть; fallback к
   доступной локали;
3. в news-store рядом с `title` хранить `title_en` и `title_ru` (если
   источник англоязычный, ru = автоперевод с пометкой "translation");
4. админская консоль умеет вводить заголовок и резюме на двух языках;
5. region labels: у CDC/ECDC они на английском, надо словарь
   en→ru-перевод стандартных названий регионов (`backend/shared/region_names.py`).

### Фаза 6: QA И Релиз (P0, 2 дня)

1. ручной чеклист на каждой публичной странице в обеих локалях:
   заголовок, h1, meta description, canonical, hreflang, og — все
   соответствуют языку;
2. Lighthouse SEO >=95 на обеих локалях;
3. визуальный QA в Playwright: десктоп + мобильный, ru + en, light + dark
   (8 скриншотов на странице);
4. тест переключения языка: state карты, выбранный регион, открытый
   feed-sheet — всё сохраняется;
5. убедиться, что pasted-ссылка `/en/methodology` от другого пользователя
   открывается сразу на en и не редиректит из-за cookie;
6. обновить README и docs/operations/runbook про локали.

## Технические Риски

- кириллица в URL: путь `/en/` остаётся ASCII; кириллических slug **не
  делаем**, чтобы не плодить punycode-проблемы;
- скрытая memoization: react-i18next кеширует строки в Suspense; нужно
  правильно настроить `i18n.options.react.useSuspense = false` или
  обернуть `App` в `<Suspense fallback={<MapLoading />}>`;
- mismatch `<html lang>` и текста: следить, что i18n меняет lang
  атрибут на body одновременно;
- SEO дубли: если en и ru будут иметь один и тот же контент по ошибке,
  поисковики накажут. Hreflang спасает только при корректной разметке;
- размер бандла: каждый язык +5-20 КБ JSON gzip. Можно lazy-load
  неактивные локали через `i18next-http-backend`.

## Что Считаем Done

- по умолчанию `/` отдаёт русский интерфейс с `<html lang="ru">`;
- переключалка RU/EN работает на десктопе и мобильном, состояние не
  теряется при смене;
- все user-facing строки в JSON-ресурсах, ни одного литерала в JSX;
- URL `/en/...` отдаёт `<html lang="en">`, корректные SEO-метатеги,
  валидный hreflang;
- sitemap содержит оба варианта каждой публичной страницы;
- Playwright e2e зелёные на ru и en;
- админская консоль на русском, поля ввода поддерживают обе локали для
  новостей.

## Открытые Вопросы

- нужен ли третий язык в обозримом будущем (es для Латинской Америки)?
  Если да — закладываем generic i18n с самого начала, чтобы не
  переписывать;
- сохранять ли user choice cookie до 1 года или 30 дней? 1 год даёт
  стабильный UX, 30 дней — больше шанса показать обновлённый ru-перевод;
- кто переводит медтерминологию? Профессиональный медпереводчик нужен
  минимум для опорных страниц фазы 2 SEO-плана.
